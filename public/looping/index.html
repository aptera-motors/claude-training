Part One

Manual Looping

🪟 Sidebar

A Quick Note on the Context Window

As you loop through a conversation, Claude holds the entire exchange in its context window — its active working memory for that session. The longer the conversation, the more of that window gets used.

For most everyday tasks this won't matter — you'll finish long before it's an issue. But in very long sessions with large documents, dense technical content, or dozens of exchanges, Claude's recall of earlier parts can start to degrade as the window fills.

The practical takeaway: for big, multi-session projects, a crisp summary prompt at the start of a new conversation ("Here's where we left off and what we're doing next…") beats an infinitely long single thread. We'll cover memory and context management in depth in a future article.

What Is Manual Looping?

Manual looping just means following up. You send a prompt, get a response, and then refine — adjust the tone, push for more depth, reformat the output, try a different angle. You stay in the conversation and build toward something genuinely useful, rather than accepting the first draft or starting over from scratch.

Think of it like working with a talented contractor. You don't hand them a napkin sketch, walk away, and hope for a finished product. You review, give feedback, and build toward something right together.

A Real-World Example

Here's what a strong opening prompt looks like — one that gives Claude enough context to actually produce something useful on the first pass:

"I need to draft an email to a new parts supplier we're onboarding — a small machine shop called Precision Fabrication Group based in San Diego. This is our first communication after they signed our NDA. The goal is to kick off the supplier qualification process. They'll need to submit three things: a completed W-9, a copy of their quality certification (we accept ISO 9001 or AS9100), and a filled-out Aptera Supplier Questionnaire (I'll attach the form separately). Tone should be professional but warm — we want them to feel like a partner, not like they're being processed. Keep it under 200 words."

That's a prompt worth sending. It names the supplier, states the context, lists the exact deliverables, specifies tone, and sets a length constraint. Claude now has everything it needs to produce a first draft that's genuinely close.

Then the loop begins:

"Good. Now tighten the opening line — it's a little stiff. And move the list of required documents into a numbered list so it's easier to scan."

"Perfect. One more pass — swap 'please submit the following' for something that sounds less like a form letter."

Three turns. Specific feedback each time. The result is something you'd actually send.

Why It Beats the "Perfect Prompt" Approach

There's a temptation to front-load everything into one massive, hyper-detailed prompt. Resist it. Iteration is faster and more reliable — perfect prompts take longer to write and still rarely produce perfect outputs.

Manual looping lets you:

  • Start strong, not perfect — a good context-rich prompt gets you 80% there on the first pass
  • Course-correct early before you're deep in the wrong direction
  • Stay in control — you shape the output through dialogue rather than trying to anticipate everything upfront

The best outputs usually come after a few refinements — and the moves are simpler than most people think: "Make it shorter." "Make it more casual." "Give me another version of option two." "Change this section but keep the rest."

You don't need to be a great prompt writer to loop well. You just need to be a good reviewer.

One Thing to Watch

Looping works best when you're refining in the right direction. If an early response is fundamentally off — wrong scope, wrong format, wrong assumptions — you have two good options:

✏️ Option 1: Edit the original prompt

Claude lets you go back and edit a previous message in the conversation. This is often the cleanest fix — you correct the source of the problem rather than layering corrections on top of a bad foundation. Use this when the issue is with how you set things up, not just with the output itself.

🆕 Option 2: Start a new conversation

If the whole direction needs to change, a fresh start with a better prompt is faster than trying to steer a derailed thread. Don't think of it as wasted effort — what you learned in the first conversation is exactly what makes the second one better.

That said, starting fresh doesn't mean losing everything. Claude can remember context from past conversations, and you can always resume a previous chat right where you left off. The richest context is always within the active session — so for complex, multi-step work, staying in one conversation gives you the most continuity.

🔑 The Manual Loop Bottom Line

One prompt gets you a draft. Looping gets you something worth using. The best Claude users at Aptera won't be the ones writing the most sophisticated prompts — they'll be the ones who know how to have a productive back-and-forth and push the conversation until the output actually fits the work.

Start strong. See what comes back. Build from there.

Part Two

Agentic Looping

"I don't prompt Claude anymore. I have loops running. They're the ones prompting Claude and figuring out what to do. My job is to write loops."

— Boris Cherny, Head of Claude Code, Anthropic

If manual looping is you having a back-and-forth conversation with Claude, agentic looping is you stepping back and letting Claude have that conversation with itself — automatically, repeatedly, until the work is done.

This is a fundamentally different way of working with AI. And it's where things get genuinely powerful.

What Is an Agentic Loop?

An agentic loop is a system that:

  • Gives Claude a goal
  • Lets Claude take an action toward that goal
  • Evaluates the result
  • Feeds that result back into Claude as the next input
  • Repeats until the goal is met

Instead of responding once, Claude acts, observes the result, decides what to do next, and repeats until a goal is actually met. The human isn't in the loop for every step — they define the goal and the rules, then let the system run.

If that structure sounds familiar, it should.

The OODA Loop Connection

Military strategists and fighter pilots have been running agentic loops for decades — they just call it something different.

Colonel John Boyd, a U.S. Air Force pilot and strategist, developed the OODA Loop as a framework for decision-making under pressure: Observe, Orient, Decide, Act — then cycle back and repeat, faster than your adversary. The pilot who completes the loop quickest wins the engagement. The commander who runs the tightest OODA loop controls the battlefield.

Agentic AI loops follow the exact same logic:

OODA Agentic Loop
Observe Claude reads the current state — a document, a dataset, an error message
Orient Claude evaluates what it sees against the goal
Decide Claude determines the next best action
Act Claude executes — writes, edits, queries, calls a tool

Then it loops. Immediately. Without waiting to be prompted again.

Boyd's insight was that speed through the loop — not raw firepower — is what creates decisive advantage. The same principle applies here. An agentic loop running overnight can complete work that would take a person days of back-and-forth prompting. The competitive advantage isn't in any single output — it's in the cycle rate.

A Real-World Example

At Anthropic's Code with Claude 2026 conference, live demos showed autonomous agents tackling real GitHub issues in production codebases — reproducing bugs, proposing fixes, running tests, iterating, and preparing pull requests with minimal human intervention.

That's an agentic loop in action. The developer didn't sit there prompting Claude step by step — they defined the task, set the parameters, and Claude worked through it autonomously, cycling through its own OODA loop until the job was done.

For Aptera, the same principle applies across many domains. Imagine a loop that monitors incoming vendor documents, extracts the relevant data, checks it against a template, flags discrepancies, and drafts a response — all without anyone prompting each step manually.

The Key Ingredients

A well-designed agentic loop needs three things:

  • A clear goal — Claude needs to know what "done" looks like
  • A feedback mechanism — each output gets evaluated and fed back in as input
  • A stop condition — a loop without a stop condition is a liability; Anthropic's own guidance explicitly lists stopping conditions like maximum iterations as a core control mechanism

Without that third ingredient, you don't have a productivity tool — you have a runaway process.
