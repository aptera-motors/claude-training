The Three Modes

Chat is where you talk. Co-Work is where you delegate. Code is where you automate. Same Claude, three very different gears.

⚡ In 30 seconds

Claude shows up in three flavors. Chat is a conversation — ask, draft, think out loud, no setup. Co-Work hands Claude the keys to your real tools (Jira, Confluence, Ramp) so it does the multi-step task instead of advising you on it. Code lives in the terminal with access to your files, servers, and APIs — it builds and runs the automation. Rule of thumb: talk → Chat, delegate → Co-Work, automate → Code.

Three quick questions. No wrong answers — just a nudge toward the right gear. .

1. What do you actually want to happen?
2. Should Claude touch your tools or files directly?
3. How comfortable are you in a terminal?

💬 Claude Chat

The conversational layer, and where most people start — for good reason. No setup, no configuration, just a conversation. Ask questions, think out loud, draft things, and get instant feedback. The right tool for anything that starts with "can you help me…"

✨ Artifacts

When Claude produces something tangible — a document, a spreadsheet, a block of code, a formatted report — it appears as an Artifact: a live, copyable output sitting alongside the conversation that you can use, download, or hand off directly.

You know that email you wrote at 4:55pm on a Friday? The one that's technically accurate but sounds like it was typed by someone who just lost an argument? Claude fixes that. Paste your draft, describe the vibe you're going for — "professional but not cold," "apologetic without groveling," "direct without sounding like a jerk" — and it rewrites it. You still sign it. It just doesn't sound like a war memo anymore.

Try saying →

Here's my draft. Make it firmer but keep it professional — we need to push back on the timeline without blowing up the relationship.

Nobody reads the pre-read. But you should at least know what's in it. Drop the agenda, the deck, or the background doc into Chat and ask Claude to brief you in plain English: what's being decided, where the likely tension is, what questions might come your way, and what you should probably say. Five minutes before walking in. Way better than scanning slides in the elevator.

Try saying →

Here's the agenda for Thursday's supplier review. What should I be ready for, and what are the two or three things I should push on?

Every company develops a dialect. Aptera's no different. ECR, BOM, DVP, NCR, GL, PO, SOX — second nature to some, total gibberish to others. Ask Claude what something means and it won't just spit out the acronym expansion. It'll explain the concept, why it matters, and how it fits into the workflow. Context included, no side-eye for asking.

Try saying →

Engineers write for engineers. Executives read for decisions. Those are two different languages, and the translation usually falls to whoever's least busy — which is nobody. Claude bridges the gap. Paste the test report, the design rationale, or the post-mortem and ask for an exec summary: what happened, why it matters, what it costs, and what you need from leadership. It strips the acronyms, kills the passive voice, leads with the bottom line, and keeps it to half a page. You keep the technical truth; you just lose the parts that make a CFO's eyes glaze over. Tell it the audience and the ask, and you'll get something you can paste straight into an email or a board slide without apologizing for the length.

Hiring is slow partly because the writing is annoying. A good job description has to sell the role, set honest expectations, and not read like every other listing on the internet. Tell Claude the title, the team, the must-haves, and the vibe you're after, and it drafts a description that sounds like Aptera — mission-forward, specific, not a wall of boilerplate. Then ask for the interview kit: behavioral and technical questions mapped to the competencies that actually matter, plus a quick rubric for what a strong, average, and weak answer looks like so your panel grades the same way. 🤝 Claude Co-Work

Where Claude stops advising and starts doing. It connects to your real tools — Jira, Confluence, Ramp, and more — and takes multi-step actions on your behalf. Drop in a transcript and it writes the minutes and files the tickets. It also has limited access to your file system: it can save files straight to a folder you grant it.

🗓️ Schedules

Tell Claude to run a task automatically on a recurring basis — pull a report every Monday, post a status every Friday, email a summary at month-end. Set it once and it runs without you, as long as your computer is on and the Claude desktop app is running.

📁 Projects

Persistent workspaces where Claude remembers context between sessions. Set up a Project for an initiative or team and Claude carries the background into every conversation — no re-explaining who you are or what you're working on.

🔌 Many tools connect to Co-Work

Jira, Confluence, and Ramp are just the ones we have today. The platform also supports NetSuite, Google Workspace, Slack, and many others — plus limited local file-system access. If you want a tool connected, ask.

Here's the workflow Co-Work replaces: someone takes notes in a meeting, emails them around, someone else creates a Confluence page, pastes things in the wrong order, and the doc sits unformatted for two weeks. Co-Work short-circuits all of it. Drop the PDF, the transcript, or the notes. Tell it which Confluence space and parent page to use. It reads the content, structures it sensibly, writes proper headings and sections, and creates the page. You review it. Done.

Try saying →

Here's the PDF from last week's supplier review. Create a Confluence page in the Manufacturing space with a summary, key decisions, and action items listed with owners.

⌨️ Claude Code

For technical work that lives in the terminal. Full access to your codebase, file system, and infrastructure. It SSHes into servers, writes and runs scripts, refactors code with tests, and connects to tools like GitHub and Confluence — operating the way a skilled developer or sysadmin would, not just suggesting what one might do.

🔁 Routines

Scheduled automations that run in the background on a defined cadence — a morning server health check, a weekly data pipeline, a nightly log rollup. Define it once and Claude Code handles it on schedule. Routines require your computer to be on and the Claude app to be running — they're local automations, not cloud-hosted jobs.

🔗 It connects to tools too

The terminal is home base, but it's not the limit. Claude Code reads and writes Confluence, pushes commits and opens PRs on GitHub, creates Jira tickets, and calls external APIs. If you can describe it in a sentence, it can usually do it end-to-end.

Claude Code with SSH access is as close as you can get to having a sysadmin on call without actually paying a sysadmin. Point it at a server, describe what's wrong or what you want to know, and it connects, runs the relevant diagnostic commands, reads the output, decides what to check next based on what it finds, and gives you a plain-English report of what it discovered and what it did. Full audit trail. Zero manual command-typing required.

Try saying →

The Jenkins server has been running slow. SSH in, check CPU and memory utilization, look at the most resource-hungry processes, and tell me if anything is obviously wrong.

Data analysis usually means: find the file, open Python or Excel, figure out the structure, write some code, fix the code, get the summary, export a chart, write it up. Claude Code handles every step. Drop the file path or describe the data source. Tell it what questions you want answered. It writes and runs the analysis code, interprets the outputs, generates summary statistics and charts, and produces a findings report — all in one go. You review the conclusions.

⚖️ Which mode should I use?

Quick reference for when each mode makes sense.

Question 💬 Chat 🤝 Co-Work ⌨️ Code
Where does it run? Browser / mobile app Browser + connected tools Your terminal / IDE
Who drives the work? You, always Claude, supervised by you Claude, with your guidance
Can it write to external tools? No Yes — Jira, Confluence, Ramp, etc. Yes — files, APIs, servers
Does it need tech setup? Just a browser login Plugin connections (one-time) CLI install + terminal access
Best for… Quick questions, drafts, thinking out loud Multi-step doc / project tasks Automations, dev work, ops tasks
Technical skill required? None None (IT sets up tools) Comfortable in a terminal

🔑 Key takeaways

  • Talk → Chat, delegate → Co-Work, automate → Code. If you only remember one thing, remember that.
  • Co-Work and Code can act on your real tools and files — Chat just talks. Reach for the higher gear when you want something done, not just answered.
  • Schedules and Routines only run while your computer is on and the Claude app is open — they're local helpers, not cloud jobs.
