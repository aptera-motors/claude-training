Choosing Your Model

Four brains, four price tags. Picking the right one is the single easiest way to get better results for less money.

⚡ In 30 seconds

Claude comes in four models. Haiku is fast and nearly free — use it for quick, simple tasks. Sonnet is the daily driver — it should handle ~90% of your work. Opus and Fable are the expensive heavyweights — reach for them only when the problem is genuinely hard. When in doubt: start with Sonnet, escalate only if it struggles.

Meet the lineup

Think of the models like vehicles in a fleet. You don't take the semi truck to grab coffee, and you don't haul a battery pack in a hatchback. Same idea here — every model can answer your question, but the cost and the depth of thinking vary enormously.

⚡
$ · cheapest

Haiku

The espresso shot — small, fast, done.

Best at: quick rewrites, short answers, simple lookups, formatting, repetitive tasks you'll run dozens of times.

  • "Make this email friendlier."
  • "What does this acronym mean?"
  • "Reformat these 40 part numbers into a table."
🚗
$$ · the default ★

Sonnet

The daily driver. Start here, always.

Best at: real everyday work — drafting docs, summarizing meetings, analyzing spreadsheets, Co-Work tasks, most coding. The best balance of smarts, speed, and cost.

  • "Summarize this meeting transcript with action items."
  • "Draft a variance analysis from these numbers."
  • "Build me a content calendar for Q3."
🏋️
$$$$ · expensive

Opus

The heavyweight. Deep thinking, deep pockets.

Best at: genuinely hard problems — complex multi-step reasoning, large-context analysis, tricky architecture decisions, work where a wrong answer is costly.

  • "Analyze these 3 supplier contracts and flag conflicting terms."
  • "Refactor this module and reason through the edge cases."
  • "Evaluate these competing battery sourcing strategies."
🧙
$$$$$ · premium

Fable

The frontier. Anthropic's most capable model.

Best at: the hardest problems, long autonomous multi-step work, and — crucially — orchestrating other models (more on that below). Overkill for everyday tasks.

  • "Plan and build this entire internal tool end-to-end."
  • "Coordinate a team of agents to audit our whole wiki."
  • "Untangle this gnarly cross-system data problem."

The cost gap is bigger than you think

This isn't a 10–20% difference. Depending on the pair you compare, the most expensive models cost 10–60× more per token than Haiku. Running your everyday email rewrites through Fable is like commissioning an architect to assemble IKEA furniture — they'll do a great job, and you'll have paid an absurd amount for an identical bookshelf.

The golden rule of model choice

Start with Sonnet. Escalate only when it struggles. If Sonnet's answer is good — and it usually is — you just saved real money. If it's clearly out of its depth on a hard problem, then re-run with Opus or Fable. Going the other direction (defaulting to the big models "just in case") quietly burns budget for zero benefit. Opus and Fable are not "better Sonnet for everything" — they're specialists you call in when the job demands it.

The 10-second decision

  1. Is it quick and simple? (rewrite, lookup, reformat) → Haiku
  2. Is it normal work? (draft, summarize, analyze, build) → Sonnet
  3. Did Sonnet struggle, or is a wrong answer expensive? → Opus
  4. Is it a huge multi-step project needing a conductor? → Fable (as the orchestrator — see below)

The power move: Fable as the conductor 🎼

Here's where it gets clever. In Claude Code (and increasingly in Co-Work), the model you're talking to can spawn sub-agents — separate Claude instances that each handle a piece of the work. And each sub-agent can run on a different model.

So instead of paying Fable prices for every word of a big project, you use Fable as the orchestrator: it does the high-level thinking — planning, breaking down the work, reviewing results — and delegates the actual labor to cheaper models matched to each task. Haiku formats the data. Sonnet writes the pages. Opus handles the one gnarly part. Fable conducts.

Fun fact: this very website was built that way. One Fable orchestrator planned the site and spawned Opus agents for the complex pages, Sonnet agents for the content pages, and Haiku agents for the FAQ and glossary — all running in parallel. Premium thinking, economy labor.

🧪 Try the orchestrator pattern

Paste this into Claude Code on a project — it explicitly asks Fable to conduct and delegate. Watch the sub-agents spin up:

You're running as Fable — act as the orchestrator for this task and spawn sub-agents on the cheapest model that can handle each piece. Task: audit our /docs folder. Spawn Haiku agents to inventory every file and flag anything not touched in 12+ months, Sonnet agents to summarize each stale doc and draft an updated version, and a single Opus agent to review the three most business-critical docs in depth. You handle the plan, coordinate the agents, and give me one consolidated report at the end. Don't do the grunt work yourself — delegate it.

Becoming a super user: what the pros know

  • You can switch models mid-conversation. Use the model picker (or /model in Claude Code) to drop from Opus back to Sonnet once the hard part is done. The conversation context carries over; the price per token drops immediately.
  • Extended thinking is a dial, not a different model. Asking Claude to "think step by step" or enabling extended thinking makes any model reason more carefully on hard problems — often Sonnet-plus-thinking beats Opus-without, at a fraction of the cost.
  • The model can't fix a vague prompt. A sharp prompt to Sonnet beats a lazy prompt to Fable every single time. If you're not getting good answers, upgrade your prompt before you upgrade your model.
  • Fresh chats matter more on big models. Long conversations re-read everything every turn — and on Opus or Fable that re-reading is expensive. Hard problem solved? Start a new chat for the next topic.
  • Every model has a finite context window. The bigger models give you more room, but quality can dip as it fills — and the size varies by model. The Context Window lesson covers how to watch it and when to compact.
  • Batch the cheap stuff. Got 30 product descriptions to clean up? That's one Haiku conversation, not 30 Sonnet ones.
  • When the stakes are high, get a second opinion. For an important deliverable, have Sonnet draft it, then ask Opus to critique it. Two models for less than the price of drafting everything on the big one.

Where do I actually pick the model?

In the Claude apps, the model picker is in the chat input area (look for the model name — click it to switch). In Claude Code, type /model. If you don't see Opus or Fable as options, that may be by design — ask Jake (jake@aptera.us) if your work genuinely needs them.

🔑 Key takeaways

  • Start with Sonnet. Drop to Haiku for quick/repetitive tasks. Escalate to Opus or Fable only when the problem genuinely demands it.
  • Opus and Fable cost many times more per token — they're specialists, not upgrades for everyday work.
  • For big projects, use Fable as an orchestrator that delegates the labor to cheaper sub-agents — premium thinking, economy execution.
